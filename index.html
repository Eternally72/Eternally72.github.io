01 System Overview

自动审查不该只是
再生成一段文字。

真正有用的代码审查，需要把变更放回项目语境里理解。 系统的目标，是帮助开发者更早聚焦值得讨论的风险，而不是制造更多噪声。

THE PROBLEM review.signal / 01
“看懂这一行”并不等于
“理解这次变更”。

单独分析 Diff 容易忽略调用关系、项目约束和业务意图。 自动审查需要先建立上下文，再判断风险，最后用开发者能够直接行动的方式交付结果。

02 Review Pipeline

从一次 Pull Request，
到一组可执行的审查意见。

这是一条围绕“理解—判断—验证—交付”设计的审查链路。 每一步都保留输入、依据与结果，便于追踪系统为什么给出某条建议。

  1. 01
    INGEST

    读取变更

    接收提交信息、Diff 和受影响文件。

  2. 02
    CONTEXT

    补全语境

    关联仓库结构、相关代码和工程规则。

  3. 03
    ANALYSE

    分析风险

    组合规则信号与模型推理形成候选发现。

  4. 04
    VERIFY

    校验证据

    检查建议是否有代码上下文和明确依据支撑。

  5. 05
    DELIVER

    交付反馈

    按位置和重要程度组织行级建议与总结。
